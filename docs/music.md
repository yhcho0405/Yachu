# 공통 배경 음악

사용자가 제공한 로비·야추·티카투카 MP3를 각각 두 곡씩 사용한다. 원본 파일은 `public/music/`, 경로·길이·음량 보정은 `src/client/music-tracks.ts`, 재생 수명은 `src/client/music.ts`가 담당한다.

아발론은 사용자가 제공한 `aval1.mp3` 한 곡을 사용한다. 같은 파일을 두 슬롯 사이에서 반복하며 곡 끝과 로비 전환에 같은 교차 페이드를 적용한다. 존재하지 않는 두 번째 파일을 요청하지 않는다. 원본은 223.5735초, 4,835,051바이트, 48kHz 스테레오이며 측정 통합 음량 −13.44 LUFS에 재생 감쇠 0.469894를 적용한다. 파일을 재인코딩하거나 편집하지 않았다.

## 재생 순서와 화면

두 곡 목록의 첫 곡은 1·2 중 무작위로 고른다. 이후 같은 상황에서는 1→2→1 또는 2→1→2로 번갈아 재생한다. 다른 화면으로 갔다 돌아와도 그 상황의 다음 순서를 이어가며, 음소거나 숨긴 탭에서 돌아오는 것은 새 곡 시작으로 세지 않는다. 페이지를 새로 열면 각 두 곡 목록의 첫 곡을 다시 무작위로 정한다.

공통 게임 목록과 방 대기실은 로비 음악, 진행 중 경기와 결과 화면은 해당 게임의 음악이다. 카드 선택이나 도움말·설정 열기는 음악을 바꾸지 않는다. 경기에서 게임 목록을 둘러보면 로비 음악으로, 다시 경기로 돌아가면 해당 게임의 다음 곡으로 전환한다. 이는 경기의 퇴장·기권과 별개다.

곡의 끝과 화면 전환에서는 1.5초 동안 이전 곡의 음량을 줄이고 다음 곡의 음량을 함께 올린다. 한 개의 공통 음악 컨텍스트와 두 개의 스트리밍 미디어 슬롯을 유지하며, 각 게임 효과음 컨텍스트는 게임 화면 수명을 따른다. 게임 화면이 사라져도 공통 BGM을 즉시 끊지 않아 교차 페이드가 이어진다. 다음 곡이 늦게 로드되면 재생 가능한 이전 곡을 유지한다.

## 설정과 브라우저

기존 `atelier.settings`의 전체 음소거와 BGM 볼륨을 그대로 사용한다. 효과음 볼륨은 음악에 영향을 주지 않는다. 이전 절차적 게임 음악은 실제 화면에서 0으로 설정하여 새 음악과 겹치지 않게 한다.

브라우저 자동재생 정책에 따라 처음 클릭·터치·키보드 동작에서 오디오를 허용받는다. 재생이 거절되면 곡 순서를 소비하지 않고 다음 동작에서 재시도한다. 숨김·음소거는 현재 위치를 보존하고, 다시 활성화하면 같은 곡을 이어간다. 빠르게 화면을 여러 번 바꾸어도 오래된 로딩 결과가 현재 선택을 덮어쓰지 않아야 한다.

앱 종료 시 미디어·노드·타이머·리스너·AudioContext를 정리한다. 음악 파일 전체를 JavaScript로 디코딩해 메모리에 쌓거나 여섯 곡을 처음부터 모두 요청하지 않는다. 파일의 출처와 측정 음량은 [자산 문서](assets.md)에 있다. 실제 검증 결과는 [검증 기록](verification.md)에 추가한다.

자동재생 처리는 WebKit의 [사용자 동작과 미디어 재생 안내](https://webkit.org/blog/6784/new-video-policies-for-ios/)와 [요소별 재생 허용 정책](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/)을 참고했다. 재사용하는 두 미디어 요소를 사용자 동작 안에서 짧은 무음 Blob으로 준비하며, 기존 CSP의 `media-src 'self' blob:` 범위를 유지한다. 이 준비는 곡 재생 순서를 소비하거나 외부 파일을 요청하지 않는다. 이 구현만으로 실제 iOS/Safari 검증까지 수행했다고 표시하지 않는다.

로컬 Static Assets 실행기에서는 MP3 Range 요청에 200 전체 응답이 와서 네이티브 `seekable` 범위가 0으로 관찰됐다. 따라서 곡 끝 검사는 시간을 강제로 이동시키는 대신 로컬 테스트에서만 원곡의 5초 구간을 재생한다. 실제 미디어 종료와 교차 페이드로 A→B→A를 확인하며, 정상 UI 검사와 운영 자산은 전체 원곡을 사용한다. 이 테스트를 위해 운영 라우팅이나 권한·게임 상태를 변경하지 않는다.
