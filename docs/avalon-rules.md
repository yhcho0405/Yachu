# 아발론 규칙과 웹 운영 정책

규칙 식별자: `avalon-base-2012-web-v1`. 기준은 Don Eskridge의 **The Resistance: Avalon 기본판**이다. 멀린·암살자를 항상 포함하며 퍼시벌·모르가나·모드레드·오베론과 호수의 여인만 선택 지원한다. Big Box 확장, 란슬롯, 원정 순서를 바꾸는 Targeting, The Resistance의 Plot 카드는 포함하지 않는다.

## 확인한 원작 자료

2026-09-06에 [제작사 소개](https://indieboardsandcards.com/our-games/the-resistance-avalon/)와 [기본판 원작 규칙서 사본 PDF](https://avalon.fun/pdfs/rules.pdf)를 직접 확인했다. PDF는 텍스트가 없는 스캔이므로 실제 페이지를 이미지로 열어 확인했다. PDF의 파일 페이지 번호 기준으로 2쪽은 인원 구성과 최초 공개 정보, 3쪽은 원정 인원, 4쪽은 찬반 투표, 5쪽은 원정 판정과 대장 순환, 6쪽은 승리와 암살, 7쪽은 선택 역할, 8쪽은 호수의 여인이다.

사용자가 지정한 [기본 규칙](https://www.ultraboardgames.com/avalon/game-rules.php), [선택 역할](https://www.ultraboardgames.com/avalon/optional-character-cards.php), [선택 규칙](https://www.ultraboardgames.com/avalon/optional-rules.php)은 PDF와 대조했다. 아래 표와 핵심 규칙의 근거는 원작 PDF이며, 웹에서 추가한 부분은 다음 절에 구분했다.

## 원작 핵심 규칙

| 인원 | 선 / 악 | 1차 | 2차 | 3차 | 4차 | 5차 |
| ---- | ------- | --- | --- | --- | --- | --- |
| 5    | 3 / 2   | 2   | 3   | 2   | 3   | 3   |
| 6    | 4 / 2   | 2   | 3   | 4   | 3   | 4   |
| 7    | 4 / 3   | 2   | 3   | 3   | 4   | 4   |
| 8    | 5 / 3   | 3   | 4   | 4   | 5   | 5   |
| 9    | 6 / 3   | 3   | 4   | 4   | 5   | 5   |
| 10   | 6 / 4   | 3   | 4   | 4   | 5   | 5   |

최초 대장과 역할은 무작위다. 대장은 자신을 포함하거나 제외하여 원정대를 제안한다. 모두 비밀 투표 후 동시에 공개한다. 과반 찬성만 가결이고 동률은 부결이다. 부결하면 대장이 시계방향으로 바뀐다. 한 원정에서 다섯 번 연속 부결하면 악이 승리한다.

승인된 원정대원만 카드를 낸다. 선은 성공만, 악은 성공·실패 중 선택한다. 작성자를 숨겨 집계하며, 실패 한 장이면 원정 실패다. **7인 이상 4차 원정만 실패 두 장이 필요하다.** 원정 종료 후 대장이 시계방향으로 바뀌고 다음 원정으로 진행한다.

원정 세 번 실패는 악의 승리다. 세 번 성공하면 역할을 공개하지 않은 채 암살자가 멀린을 지목한다. 정답이면 악, 오답이면 선이 승리한다.

### 역할별 최초 정보

| 역할                          | 진영 | 제공되는 정보                                           |
| ----------------------------- | ---- | ------------------------------------------------------- |
| 멀린                          | 선   | 모드레드를 제외한 악의 인물. 오베론은 보인다.           |
| 퍼시벌                        | 선   | 멀린 후보. 모르가나가 있으면 두 후보를 구별하지 못한다. |
| 충신                          | 선   | 자신의 역할만                                           |
| 암살자·모르가나·모드레드·수하 | 악   | 오베론을 제외한 악의 동료. 동료의 상세 역할은 제외한다. |
| 오베론                        | 악   | 자신의 역할만. 다른 악과 서로 동료 정보를 받지 않는다.  |

특수 역할은 중복할 수 없고 인원별 진영 수를 넘을 수 없다. 5인 퍼시벌에는 모르가나 또는 모드레드를 함께 사용한다.

### 호수의 여인

최초 토큰은 대장의 오른쪽 사람에게 간다. 2·3·4차 원정 직후 소유자가 한 사람의 **진영만** 확인하고, 대상이 토큰을 받는다. 자신과 이미 토큰을 사용했던 사람은 조사할 수 없다. 최대 세 번 사용한다. 확인한 내용에 관해 주장하거나 거짓말할 수 있지만 진영 카드를 공개하지 않는다. 원작의 7인 이상 권장은 최소 인원 제한과 다르다.

## 웹에서 정한 운영 정책

다음은 물리 보드게임의 기본 규칙을 온라인으로 운영하기 위한 정책이다.

- **고정 좌석:** 로비에서 퇴장으로 빈 번호가 생겼다면, 시작 시 기존 좌석의 순서를 유지하면서 내부 번호를 `0..인원-1`로 정리한다. 화면에는 1번부터 연속으로 표시한다. 설정 검증과 역할·대장 난수 생성이 모두 성공한 뒤 정리하므로 시작 실패는 좌석을 바꾸지 않는다. 번호가 증가하는 방향이 시계방향이며 마지막 좌석 다음은 첫 좌석이다. 최초 호수의 여인 소유자는 최초 대장의 바로 이전 좌석이다. 시작 후에는 이 번호를 고정하고 재접속·방장 변경으로 역할·좌석·대장을 재배정하지 않는다. 진행 중·종료 상태의 저장 검증도 연속 좌석을 요구한다.
- **구성 확인:** 멀린과 암살자는 필수다. 로비에서 선택 설정을 공개하며, 구성을 바꾸면 전원의 준비가 해제된다. 인원이 부족하거나 선택 악 역할이 진영 수를 넘는 로비 설정은 저장할 수 있지만 시작 불가 사유를 표시하고 시작을 거절한다. 시작 후 구성 변경은 불가능하다. 호수의 여인은 기본 비활성이고 5·6인에서도 켤 수 있으며 권장 인원을 안내한다.
- **초안과 확정:** 원정대 초안, 찬반 선택, 카드 선택, 암살 대상 선택은 해당 사용자의 로컬 UI 상태다. 최종 제출만 전송한다. 개인 역할 패널 열기와 메모 역시 서버로 보내지 않는다.
- **전원 제출:** 별도 대장의 공개 버튼 없이 마지막 제출과 집계를 같은 트랜잭션에서 처리한다. 제출자는 좌석 순으로 표시하며 카드 종류에 따른 표시·소리 차이를 두지 않는다. 제출을 취소하거나 바꿀 수 없다. 승인되면 연속 부결 수를 즉시 0으로 초기화한다.
- **호수의 여인과 종료 우선순위:** 원작의 즉시 종료 조건을 우선한다. 세 번째 성공 뒤에는 암살로, 세 번째 실패 뒤에는 최종 결과로 이동하며 추가 조사를 하지 않는다. 조사가 필요한 원정 직후에는 대장 이동을 먼저 공개하고, 조사가 끝나면 다음 원정 구성으로 이동한다. 진영은 서버가 판정하므로 물리 카드의 거짓 제출 절차는 없다.
- **암살 대상:** 원문은 선의 인물을 지목하도록 설명한다. 웹에서는 숨은 진영을 버튼 목록이나 오류 응답으로 알아내지 못하도록 **본인 외 모든 고정 좌석**을 선택할 수 있다. 멀린이 아닌 대상을 확정하면 바로 오답으로 종료한다. 악을 지목했다는 이유로 재선택 기회를 주지 않는다. 암살 단계의 공개 `turnPlayerId`는 `null`이며, 암살자 자신의 수신 정보만 최종 선택 권한을 만든다.
- **연결 종료:** 진행 중 인원 대체, AI 대체, 개인 기권 승패는 없다. 참가자의 누적 재접속 유예는 경기당 120초이며 재접속으로 충전되지 않는다. 유예 소진이나 명시적 나가기처럼 고정 인원을 유지할 수 없으면 경기 전체를 무효 종료한다. 특정 진영에 승리를 주지 않고 전체 역할을 공개하지 않는다. 본인이 이미 알고 있던 정보만 자신의 화면에 남는다. 재경기는 로비에서 새 경기 ID로 진행한다.
- **토론:** 방 전체 채팅은 공개 주장이다. 신뢰·의심·질문·발언 요청·동의 반응 역시 발신자의 의견이다. 역할의 사실 확인 표시와 구분한다. HTML 실행 없이 텍스트로 렌더링한다. 채팅은 300자, 최근 100개를 보관하며 반응은 최근 30개를 보관한다. 서버가 빈도와 중복을 제한한다.
- **진행 시간:** 애니메이션 완료와 상태 확정은 독립적이다. 토론을 임의로 끝내거나 역할에 따라 자동 찬반·원정 카드를 제출하지 않는다. 서버는 제출된 명령으로만 진행하며 연결 유지와 방 만료는 공통 방 관리 정책을 따른다.

## 상태와 정보 경계

`src/shared/avalon.ts`는 세 가지 타입을 분리한다.

| 타입                  | 용도                                     | 비공개 데이터                                                                   |
| --------------------- | ---------------------------------------- | ------------------------------------------------------------------------------- |
| `AvalonInternalState` | SQLite에 저장하는 서버 상태              | `secrets`의 역할 배정, 미집계 제출, 조사 결과                                   |
| `AvalonPublicState`   | 공용 3D 보드와 공개 UI                   | 없음                                                                            |
| `AvalonRoomState`     | 특정 수신자의 HTTP·WebSocket·요청 영수증 | `privateInfo`의 자기 역할, 허용된 인물 목록, 자기 미집계 제출, 자신의 조사 결과 |

`projectAvalonPublic`은 모든 중첩 객체를 명시적인 허용 필드만으로 새로 만든다. 원본 상태를 펼친 뒤 비밀 필드를 지우는 방식은 사용하지 않는다. `projectAvalon`은 이 공개 객체에 수신자에게 허용된 정보만 추가한다. 방장에게 별도의 역할 열람 권한은 없다. 반환 객체를 변경해도 저장된 역할이나 다른 수신자의 응답은 바뀌지 않는다.

찬반은 미집계 중에는 자기 선택과 공개 제출 여부만 전달하고, 집계가 끝나면 모든 개인 찬반을 공개 기록으로 저장한다. 원정은 집계 전에는 자기 카드와 제출 여부만 전달한다. 완료 시 **현재 경기 상태의 작성자별 카드 맵을 제거**하고 성공 수·실패 수·판정만 남긴다. 중복 요청 복구를 위한 원본 명령과 최초 영수증은 별도 서버 저장소에 보존하며, 영수증은 인증된 요청자 본인에게만 다시 반환한다. 공개 카드 배열, 카드 ID, 카드 순서, 카드별 작성자나 제출 시각은 존재하지 않는다. 결과 연출도 이 익명 집계로 구성한다. 정상 종료의 역할 공개로 과거 원정 카드 매핑이 참가자에게 전달되지는 않는다.

역할과 최초 대장은 서버가 주입한 안전한 주사위 난수를 사용한다. 두 번의 균등 주사위 결과로 36가지 표본을 만들고 나머지 편향이 생기는 표본을 거절하여 1~10개의 선택지를 균등 선택한다. 역할은 Fisher–Yates 방식으로 섞는다. 클라이언트가 난수나 역할을 지정할 명령은 없다. 원정 결과는 순서를 갖는 카드 대신 집계만 제공하므로, 카드 순서 익명화를 위한 추가 난수나 식별자가 필요하지 않다.

## 동시 명령과 복구

규칙 명령은 `gameId`와 `phaseId`, `proposalId`로 현재 경기를 확인한다. `phaseId`는 단계가 바뀌거나 로비의 역할·옵션 설정을 변경할 때 새로 생성하고 같은 값을 공통 `turnId`에도 둔다. 같은 단계에서 다른 참가자가 투표하거나 채팅·연결 상태가 바뀌어도 해당 투표의 유효 기간은 끝나지 않는다. 제출자는 한 번만 반영한다. 이전 단계·다른 제안의 제출은 거절한다.

요청 ID 중복 방지, 내용이 다른 재사용 거절, SQLite 원자 저장, 연결 권한과 수신자별 영수증 반환은 공통 서버가 담당한다. 순수 엔진은 시간과 난수 함수를 외부에서 주입받으며 네트워크·DOM·오디오·저장소에 접근하지 않는다. `isAvalonInternalState`와 `isAvalonRoomState`는 서로 다른 저장·수신 형식을 엄격하게 검사한다. 비밀 상태를 공개 영수증으로 착각하거나, 원정 기록에 작성자 필드를 추가한 데이터는 통과하지 못한다.

## 검증 근거

`tests/avalon.test.ts`는 인원표 전체, 96개 인원·역할 조합, 균등 선택 표본, 동률과 5회 부결, 동시 제출 범위, 4차 원정 예외, 암살 양쪽 결과, 호수의 여인 세 번과 종료 우선순위, JSON 재접속 복구, 무효 종료를 확인한다. 비연속 로비 좌석을 정리한 5인 경기에서 역할·대장·호수의 여인 전달은 같은 신원에 연결되고 재접속 후 번호도 유지되는지 검사한다. 설정 또는 마지막 대장 난수 생성이 실패하면 원래 좌석이 그대로인지도 검증한다. 역할 배정만 바꾸어 권한 없는 수신자의 응답이 같음을 비교하고, 동일한 원정 집계에서 작성자별 카드 선택을 바꿔도 공개 응답이 같음을 검증한다.

이 문서의 순수 규칙 검증은 실제 HTTP·WebSocket, 브라우저, 배포 검증의 대체가 아니다. 원자 저장·실제 런타임 복구와 화면 검증은 별도의 통합 테스트 및 `docs/verification.md`의 실행 결과를 따른다.
