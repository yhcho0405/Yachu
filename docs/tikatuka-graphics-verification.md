# 티카투카 장면·오디오 검증

확인일: 2026-09-06. macOS arm64, Playwright Chromium 153.0.8010.12의 일반 headful 실행을 사용했다. 강제 SwiftShader 옵션은 사용하지 않았다. 실제 WebGL renderer는 `ANGLE (Apple, ANGLE Metal Renderer: Apple M5 Pro, Unspecified Version)`이다. 실제 소리 청취는 하지 않았으며, 아래 오디오는 자동 신호·수명주기 확인이다.

## 실제 게임 UI

Vite 클라이언트에서 로컬 workerd의 실제 API·WebSocket을 사용한 일반 신규 게스트 혼자 대전을 진행했다. 주사위 난수나 서버 판단을 바꾸지 않았다. 직접 3D 보드 클릭→선택 확정, 특수 재굴림→기존 주사위 선택, 이후 5회 배치를 확인했다. 장면 오류와 페이지 JavaScript 오류는 없었다.

- 1366×900에서 현재 주사위와 배치된 9개 주사위의 최종 윗면이 각각 서버 값과 일치했다. 목재 바닥이 테두리 아래에 실제로 들어가고, 둥근 주사위가 접촉 그림자 위에 앉는 것을 스크린샷으로 확인했다.
- 360×900에서 문서 폭은 360px으로 가로 넘침이 없고, 보드 영역은 약 332×490px이다. 상대가 위, 내가 아래에 보이며 세 열의 대응 점수는 같은 방향으로 읽힌다. 두 실드 표시와 일반 주사위 눈이 가려지지 않는다.
- 900×900에서도 가로 넘침이 없었다. 좁은 가로형 보드가 불필요하게 세로형으로 회전하는 것을 막기 위해 세로 여유가 충분한 영역만 압축 레이아웃을 사용한다. 수정 후 별도 일반 신규 게스트 대전에서도 546×425px 보드가 좌우 대응 줄을 유지함을 재확인했다 (`work/tika-ui-tablet-final.png`).
- 정지된 상태의 1초 동안 장면 RAF 호출은 0회였다. 활성 canvas는 1개, AudioContext는 1개였다.
- 실제 UI의 배경 음악 신호 표본 RMS는 0.000769, peak는 0.001544였다. 이 표본은 효과음 전체의 음질 청취 평가가 아니다.

로컬 근거는 `work/tika-ui-graphics.json`, `work/tika-ui-desktop.png`, `work/tika-ui-360.png`, `work/tika-ui-900.png` 및 `work/tika-ui-video/`에 있다. `work/`는 테스트 과정의 민감한 방 식별자가 포함될 수 있어 저장소에 커밋하지 않는다.

## 공격·재굴림의 격리 연출 검사

모든 서버 사건을 우연히 한 경기에서 얻는 대신, 실제 scene 모듈에 구체적인 읽기 전용 상태 예제를 전달한 별도 진단 페이지에서도 확인했다. 이 예제는 일반 플레이의 결과나 원작 영상이라고 표시하지 않는다.

상대 줄 `[일반5, 실드5, 일반5]`를 일반5로 공격하는 예제에서 다음을 확인했다.

1. 470ms 접촉 전에 공격자와 제거 대상이 보이며 보너스는 보이지 않는다.
2. 접촉 후 일반 주사위 2개와 공격 주사위가 움직이며 사라지고 실드5는 남는다. 공격 효과음 콜백은 실제 접촉 단계에서 1회 발생한다.
3. 920–1180ms에 남은 실드가 빈자리를 메운다. 1000ms 표본에는 공격자와 제거 대상이 없고 보너스도 아직 없다.
4. 1180ms 이후에 서버 예제에 포함된 새 보너스 실드4가 등장해 굴러간다. 이 결과를 장면이 임의로 생성하지 않는다.
5. 완료 시 모든 윗면이 확정 값과 같고, 원래/재굴림 실드 후보 4와 2를 함께 표시한 다음 기존 4를 선택하면 하나만 남는다.

같은 이벤트를 입력 상태 변화 때문에 `animate:false`로 다시 전달해도 진행 중인 공격은 취소되지 않는다. 반대로 모션 감소 상태의 새 이벤트는 소리나 지연 없이 최신 확정 장면을 표시한다. 데스크톱과 모바일의 직접 raycast 입력이 동일한 `{ownerId, lane}`을 돌려주는 것도 확인했다.

로컬 근거: `work/tika-scene-timeline.json`, `work/tika-attack-contact.png`, `work/tika-reroll-candidates.png`. `work/tika-scene-attack-demo.webm`은 화면에 격리 진단이라고 표시한 5.40초·1200×760·25fps 무음 기록이다. 녹화 프레임레이트를 실제 게임의 렌더링 FPS로 해석하지 않는다.

## 수학·오디오·정리

`tests/tikatuka-motion.test.ts`의 두 테스트가 통과했다. 6개 눈 각각 701개 시점에서 독립적인 둥근 모서리 투영을 계산하여 바닥 침범이 없음을 확인하고, 마지막 자세가 연속적으로 정확한 면으로 수렴하는지 검사한다. 양쪽의 18개 칸은 두 레이아웃에서 서로 겹치지 않고 대응 줄을 유지한다. 기존 공통 orientation 테스트도 그대로 유지한다.

`work/tika-audio-check.json`의 별도 실제 AudioContext 진단에서 사용자 제스처 전 컨텍스트 수는 0이었다. 15종 이벤트를 의도적으로 겹쳐 재생한 표본은 RMS 0.03218, peak 0.12155로 limiter의 상한 아래였고, 전체 음소거 후 RMS와 peak는 모두 0이었다. dispose 후 컨텍스트는 `closed`였다. 동시 발음 수는 최대 40이며 음악과 효과음은 별도 gain 뒤 compressor와 bounded waveshaper를 지난다.

장면은 ResizeObserver·포인터·visibility·컨텍스트 이벤트를 해제하고 RAF·geometry·material·texture·shadow·환경 맵·WebGL context를 dispose한다. 숨김 처리와 컨텍스트 복구 경로는 코드를 검토했으며, 이번 티카투카 검사에서 실제 운영체제의 document.hidden 전환이나 실제 음향 청취를 검증했다고 주장하지 않는다.
