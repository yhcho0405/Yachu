# 그래픽·오디오 검증 기록

검증일: 2026-09-06. 아래 게임 흐름은 `http://127.0.0.1:8787`의 실제 Wrangler Worker 및 Durable Objects에 일반 게스트 UI로 접속해 수행했다. 주사위 지정 또는 인증 우회 경로를 사용하지 않았다.

## 실행과 증거

```sh
npm run dev
# 다른 터미널: 실제 GPU를 사용하는 화면 있는 Chromium
GRAPHICS_RECORD=1 node scripts/graphics-qa.mjs
# 실제 점수 선택·확정까지 담는 짧은 플레이 녹화
node scripts/graphics-record.mjs
# 녹화 없이 두 번의 굴림 성능 프로파일
node scripts/graphics-profile.mjs
# GPU가 없는 자동화 환경의 별도 경량 렌더링 검증
GRAPHICS_SOFTWARE=1 node scripts/graphics-qa.mjs
```

브라우저 설치는 README의 Playwright 준비 명령을 따른다. `GRAPHICS_BASE_URL`로 다른 승인된 테스트 출처를 지정할 수 있다. 테스트는 별도 브라우저 컨텍스트와 게스트 방을 만든다. 토큰·쿠키·서버 응답 원문은 증거 파일에 저장하지 않는다.

- `media/graphics-report.json`: 실제 GPU에서 수행한 조작·렌더링·음소거 검증 결과.
- `media/hardware-profile.json`: 녹화 없는 별도 두 굴림 성능 표본.
- `media/home-desktop.png`, `game-desktop.png`, `held-desktop.png`: 직접 확인한 기본 화면과 실제 게임·보관 장면. `media/gameplay-final-desktop.png`는 초이스 23점 확정 후 2라운드를 진행하는 최종 대표 화면이다.
- `media/game-mobile-360.png`, `game-tablet-900.png`: 360px·900px 화면 폭의 실제 브라우저 캡처.
- `media/context-loss-fallback.png`: WebGL 컨텍스트 손실 중 한국어 안내와 HTML 주사위·점수표.
- `media/gameplay-local.webm`: 7.52초, 1366×900, VP8, 25fps의 조작 녹화. 영상 파일의 프레임률은 게임의 실제 렌더링 프레임률과 다르다. 실제 굴림 → 두 개 보관 → 재굴림 → 점수 선택·확정 → 다음 턴 굴림을 담았다. 이 녹화에는 오디오 트랙이 없다. 주사위끼리 맞닿는 발사 동작을 추가하기 전 녹화이며, 해당 후속 변경은 아래 별도 접촉 캡처와 콜백 기록으로 검증했다. 최종 녹화의 2초·5초 프레임을 추출해 직접 확인했다.

위 캡처는 최종 통합된 반응형 UI에서 확인했다. 데스크톱 점수 항목 13px, 더 큰 플레이 영역, 모바일 점수 터치 영역 최소 44px, 참가 버튼 한 줄 표시와 1인 점수표 이름 표시를 실제 캡처에서 재확인했다. 이후 레이아웃을 변경하면 동일 검증 명령으로 캡처와 결과를 함께 갱신한다.

## 실제 하드웨어 성능

- 기기: macOS arm64, **Apple M5 Pro** GPU.
- 브라우저: 화면 있는 Chromium **153.0.8010.12**, 강제 그래픽 플래그 없음.
- WebGL: `ANGLE (Apple, ANGLE Metal Renderer: Apple M5 Pro, Unspecified Version)`.
- 뷰포트: **1366×900 CSS px, DPR 1**. 화면 폭 축소는 모바일 에뮬레이션이며 실제 휴대폰 성능이라고 주장하지 않는다.
- 초기 두 번의 프로파일 당시에는 별도의 4인 소프트웨어 렌더링 테스트가 같은 호스트에서 병행 중이었다. 최종 UI QA는 영상 녹화 없이 측정했고, 짧은 플레이 영상은 별도 일반 게임 경로로 녹화했다.

| 조건                  | 1.1초 굴림의 프레임 수 | RAF 간격 중앙값 / p95 | JS 콜백 시간 중앙값 / p95 |
| --------------------- | ---------------------- | --------------------- | ------------------------- |
| 녹화 없음, 1차        | 132                    | 8.3ms / 9.8ms         | 0.3ms / 0.5ms             |
| 녹화 없음, 2차        | 133                    | 8.3ms / 10.0ms        | 0.3ms / 0.4ms             |
| 최종 UI QA, 녹화 없음 | 132                    | 8.3ms / 9.2ms         | 0.3ms / 0.4ms             |

이 호스트에서는 약 120Hz의 RAF 주기로 실행되어 60fps 목표를 충분히 충족했다. 실제 디스플레이의 모든 표시 프레임을 별도 카메라로 측정한 값은 아니며, JavaScript RAF 간격과 콜백 시간의 측정이다. 일반 모바일 기기의 60fps까지 이 수치로 보장하지 않는다.

초기 SwiftShader + 영상 녹화 + 병렬 브라우저 조건에서는 굴림 8프레임, 중앙 RAF 간격 약 166.6ms가 관찰됐다. 이를 하드웨어 브라우저 성능으로 표기하지 않는다. 초기 GPU 작업이 작은 CPU와 소프트웨어 래스터라이저를 오래 막지 않도록, 실제 렌더러와 하드웨어 스레드 수에 따라 시작부터 환경 반사 맵 베이킹·동적 그림자를 생략하고 DPR 1의 경량 모드를 선택하도록 수정했다. 이후 느린 프레임은 개수뿐 아니라 경과 시간으로 화질을 낮추며, 가장 낮은 단계에도 접촉 그림자를 유지한다.

## 실제 오디오 검증 범위

첫 사용자 동작 전 AudioContext는 **0개**였다. 첫 동작 후 48kHz AudioContext **1개**에서 효과음과 음악이 재생됐다. 출력에 연결한 analyser의 신호는 음소거 전 RMS **0.003517**, peak **0.006779**, 음소거 후 RMS와 peak 모두 **0**이었다. 설정은 새로고침 뒤 유지됐다.

이는 브라우저 자동재생 제한, 실제 신호 생성 및 음소거의 자동 검증이다. 개발 도구를 통한 실제 스피커 청취는 수행하지 못했으므로 음질을 청취 검증했다고 주장하지 않는다. 원작 음악도 청취·추출하지 않았다. 다른 탭을 열고 앞으로 가져와 비활성화를 시험했으나, 이 자동화 브라우저는 원래 페이지의 `document.hidden`을 계속 `false`로 보고했다. 따라서 이 실행은 실제 background suspension을 검증한 것으로 계산하지 않는다. 복귀 후 AudioContext 1개가 running 상태이며 지나간 굴림이 재생되지 않은 것은 확인했다. 실제 hidden 이벤트 시 RAF 취소·오디오 정지, 복귀 시 최신 상태 정착과 자원 해제는 별도 코드 검토로 확인했다.

## 검증에서 발견해 고친 그래픽 문제

- 안쪽 트레이의 바닥판이 펠트보다 높아 천과 인쇄를 가리던 문제를 수정했다. 둥근 윤곽과 속이 빈 벽으로 층과 접촉을 분리했다.
- 낮은 높이의 RoundedBox는 평면 모서리도 지나치게 작아지는 문제가 있어, 트레이는 독립적인 평면 곡률을 갖는 압출 지오메트리로 바꿨다.
- 보관 이동까지 UI 입력을 잠그던 연출 알림을 굴림 전용으로 바꿨다. 연속 보관과 곧바로 굴리기를 지원한다.
- 매우 느린 장치에서 한 굴림의 프레임 수가 적어 화질 조정이 발동하지 않던 기준을 경과 시간으로 보완했다.
- 컨텍스트 복구 후 환경 반사 render target의 내용이 사라져 색이 어두워지던 문제를 고쳤다. 일반 GPU에서는 PMREM을 다시 생성한다. 수정 후 별도 장면에서 복구 전후 캡처의 평균 RGB 절대 차이가 채널별 **0.006 / 255 미만**임을 확인했다 (`media/context-scene-before.png`, `media/context-scene-after.png`).

## 주사위 접촉과 충돌음 후속 검증

둘 이상 굴릴 때 첫 두 주사위가 220ms 지점에서 같은 기울기로 실제 옆면을 맞댄 뒤 각자의 경로로 돌아간다. 둥근 상자의 정확한 X축 지지 거리를 유지하여 겹치지 않으며, 접촉 시 한 번 발생하는 `onCollision`을 별도의 짧은 주사위 충돌음에 연결했다. 트레이 착지음은 기존 세 번의 바운스에 연결되어 있다.

화면 있는 Chromium 153.0.8010.12 / Apple M5 Pro Metal / 1000×700 / DPR 1에서 실제 장면 모듈의 콜백과 최종 면을 추가 검증했다. 다섯 개 굴림은 221ms, 떨어져 있는 0·4번만 굴림은 229ms에 각각 충돌 콜백이 정확히 한 번 발생했다. 한 개만 굴림, 효과 줄이기, 재접속의 즉시 복원, 발사 도중 70ms에 효과 줄이기를 켠 경우에는 충돌 콜백이 없었다. 여섯 경우 모두 최종 윗면은 요청 값 `[6,5,4,3,2]`와 일치했고 JavaScript 오류는 없었으며 dispose 후 캔버스가 제거됐다. `media/dice-contact.png`에서 실제 옆면 접촉을 직접 확인했다. 수치 기록은 `media/dice-contact-report.json`에 있다. 이 검증 역시 스피커 청취를 포함하지 않는다.

`tests/dice-contact.test.ts`는 가능한 31개 굴림 부분집합을 각각 201개 시점에서 검사한다. 트레이에서 시작하는 경우와 보관대에서 방금 해제한 경우를 모두 포함하여, 회전된 둥근 상자의 모서리를 독립적으로 투영해 바닥 지지와 모든 주사위 쌍의 분리를 확인한다. 정확한 0.95 옆면 접촉, 두 구간 경계의 quaternion 연속성, 여섯 서버 값의 최종 윗면도 통과했다. 담당 소스·테스트의 ESLint와 TypeScript 검사를 통과했다.

추가 background 검증에서는 Chromium의 background 제한 관련 기본 플래그를 제거한 뒤 두 번째 탭 활성화와 네이티브 창 최소화를 시도했다. 모두 `document.hidden=false`가 유지되어 실제 visibilitychange 및 오디오 suspend/resume을 검증하지 못했다. 위에 명시한 자동화 한계는 그대로 적용된다.
