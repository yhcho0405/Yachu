## 실제 브라우저에서 확인한 범위

- **1·2·3·4인 각각** 별도 쿠키/게스트 세션의 독립 컨텍스트로 방 생성, 초대 링크 참가, 준비, 시작, 12라운드 완료, 순위, 같은 방의 재경기 및 첫 굴림까지 통과했다.
- 전체 참가자의 WebSocket으로 받은 경기 ID, 상태 버전, 주사위 값·보관, 점수, 현재 턴이 서버 스냅샷과 일치했다.
- 빠르게 두 주사위를 보관한 뒤 재굴림해 보관값이 유지됐다. 새로고침과 네트워크 차단·복구 후 같은 좌석과 확정 상태가 유지됐다.
- 서버가 굴림을 저장한 뒤 HTTP 응답만 유실시키고 새로고침했다. 처음과 같은 요청 ID·내용을 재전송해 굴림 횟수와 결과가 바뀌지 않았다.
- 같은 세션의 새 탭이 연결을 이어받았고, 이전 탭의 종료가 새 연결을 끊김으로 덮어쓰지 않았다.
- **Chromium 및 Firefox**, 360×800 세로와 800×360 가로 화면에서 굴림·보관·점수 확정과 문서 가로 넘침을 확인했다.
- 같은 닉네임을 가진 독립 세션5개로 마지막 좌석 동시 참가를 시도했으며 정확히1명만 마지막 자리를 얻었다.
- 로컬 환경에서 비참가자·다른 차례·잘못된 요청·CSRF·Origin·세션 폐기·중복 및 오래된 요청 거부를 확인했다. 실제 WebSocket 명령 경로도 별도로 검증했다.
- 정적 파일·SPA 직접 경로·API의 보안 헤더와 JSON 라우팅, `/version.json`과 `/api/health`의 동일 커밋 식별자를 확인했다.

## 그래픽·오디오

[별도 측정 기록](graphics-verification.md)에 브라우저·GPU·해상도·조건과 결과를 구분해 기록했다. Apple M5 Pro의 하드웨어 가속 Chromium, 1366×900에서 굴림 RAF 중앙값8.3ms를 관찰했다. 소프트웨어 렌더러에는 초기부터 가벼운 그래픽 경로를 제공한다. 이는 모든 모바일 기기의60fps를 보장하는 수치가 아니다.

실제 캔버스 마우스·터치 선택, 서버 값과 최종 윗면, 효과 줄이기, 설정 저장, WebGL 손실/복구, 오디오 출력 신호와 음소거를 확인했다. 스피커를 통한 실제 음질 청취는 수행하지 않았다. 영상에는 오디오 트랙이 없다.

## 운영 배포 검증

`main`의 검증된 커밋만 GitHub Actions에서 배포한다. 배포 직후 Wrangler가 반환한 실제 `workers.dev` 주소에서 동일한 Playwright 검사를 다시 실행하고 `EXPECTED_COMMIT`으로 서버와 정적 자산의 SHA를 확인한다. 운영에서는 로컬 전용 권한/오류 주입 테스트2개를 건너뛰고 정상 사용자 흐름8개를 수행한다.

각 배포의 **실제 URL·커밋 SHA·운영 검증 성공/실패는 해당 Actions 실행 요약과 `live-browser-results-<SHA>` 아티팩트에 기록**된다. 이 문서는 배포 전 로컬 결과를 고정해 보관하며, 아직 실행하지 않은 배포의 성공을 선언하지 않는다. 실패한 검사나 배포를 성공으로 표시하지 않는다.

## CI 실행 중 확인한 문제

[초기 수정본의 CI](https://github.com/yhcho0405/Yachu/actions/runs/34021937471)는1·2·3인 경기까지 통과했으나4인 경기 중 로컬 Wrangler 프로세스가 종료되어 실패했다. [진단을 추가한 실행](https://github.com/yhcho0405/Yachu/actions/runs/34022991988)도 약1분 후 빈 오류와 exit code 1로 종료됐다. 두 실행 모두 배포 단계에 도달하지 않았다. 진단 당시 가용 메모리는 약14GB였으며 메모리 부족으로 단정할 근거는 없었다.

고정된 Wrangler SDK의 `ProxyController`와 오류 전달 코드를 확인했다. Cloudflare의 [동일 증상 이슈 #15317](https://github.com/cloudflare/workers-sdk/issues/15317)와 [요청 단위 프록시 오류를 치명적 종료로 처리하지 않도록 하는 PR #15207](https://github.com/cloudflare/workers-sdk/pull/15207)가 이 동작을 설명한다. 이는 우리 실행의 증상과 코드 경로에 일치하지만, 개별 연결이 끊긴 최초 원인까지 확정했다는 뜻은 아니다. 확인 시점에 PR은 미병합 상태였다.

CI는 Wrangler CLI의 추가 개발 프록시를 거치지 않고 같은 Wrangler가 사용하는 실제 Miniflare/workerd를 시작하도록 변경했다. `wrangler.jsonc`를 SDK로 변환하므로 Worker·DO 바인딩·SQLite·정적 자산·헤더가 다른 설정으로 갈라지지 않는다. 배포할 동일 번들을 사용하며 게임 코드와 브라우저 테스트, 실패 시 배포 중단 조건은 유지한다. 일반 로컬 개발과 별도 재시작 영속성 검사는 여전히 Wrangler CLI를 사용한다. 미병합 SDK 코드를 설치하거나 SDK를 패치하지 않았다. 원문 개발 로그·요청 헤더·쿠키·설정은 업로드하지 않는다. 실패한 실행을 성공으로 집계하지 않으며, 후속 전체 실행의 결과는 Actions에 남긴다.

변경한 CI 실행 방식으로 로컬에서 전체 Playwright **10개 통과, 실패0, 재시도0(6.1분)**를 다시 확인했다. 30개 단위 테스트·요청 큐 검사·Wrangler 재시작 영속성 검사도 통과했다. 분리된 인스턴스의 native workerd 강제 종료가 CI 서버의 exit code 1로 이어짐을 확인하여 자동 재시작으로 실패가 숨겨지지 않게 했다. 임의의 입력·토큰 모양 문자열을 사용한 로그 필터 검사도 통과했으며 실제 credential은 사용하지 않았다.

## 알려진 한계

실제 휴대폰 하드웨어, Safari/iOS, 수백 방 규모의 부하와 전체 기기 호환성은 검사하지 않았다. Cloudflare 대시보드에서 현재 Workers Free 플랜을 확인했으며 요금제나 결제 설정은 변경하지 않았다. 사용량 한도는 배포 문서에 기록했다. 작은 친구 모임을 위한 단일 세션 Registry 구조이며, 대규모 공개 서비스의 처리량을 검증한 설계는 아니다. 무료 한도를 넘지 않는다고 보장하지 않는다. 자동 검사로 관찰한 사운드 신호와 실제 청취를 구분한다.
