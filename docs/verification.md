## 기존 야추 단독 버전의 운영 배포 검증

`main`의 검증된 커밋만 GitHub Actions에서 배포한다. 배포 직후 Wrangler가 반환한 실제 `workers.dev` 주소에서 동일한 Playwright 검사를 다시 실행하고 `EXPECTED_COMMIT`으로 서버와 정적 자산의 SHA를 확인한다. 이 야추 단독 버전의 운영 검사에서는 로컬 전용 권한/오류 주입 테스트2개를 건너뛰고 정상 사용자 흐름8개를 수행했다. 새 멀티게임 구성의 검사 수와 수행 여부는 아래 별도 절을 따른다.

각 배포의 **실제 URL·커밋 SHA·운영 검증 성공/실패는 해당 Actions 실행 요약과 `live-browser-results-<SHA>` 아티팩트에 기록**된다. 이 문서는 배포 전 로컬 결과를 고정해 보관하며, 아직 실행하지 않은 배포의 성공을 선언하지 않는다. 실패한 검사나 배포를 성공으로 표시하지 않는다.

## CI 실행 중 확인한 문제

[초기 수정본의 CI](https://github.com/yhcho0405/Yachu/actions/runs/34021937471)는1·2·3인 경기까지 통과했으나4인 경기 중 로컬 Wrangler 프로세스가 종료되어 실패했다. CI는 Wrangler CLI의 추가 개발 프록시를 거치지 않고 같은 Wrangler가 사용하는 실제 Miniflare/workerd를 시작하도록 변경했다. `wrangler.jsonc`를 SDK로 변환하므로 Worker·DO 바인딩·SQLite·정적 자산·헤더가 다른 설정으로 갈라지지 않는다. 배포할 동일 번들을 사용하며 게임 코드와 브라우저 테스트, 실패 시 배포 중단 조건은 유지한다. 일반 로컬 개발과 별도 재시작 영속성 검사는 여전히 Wrangler CLI를 사용한다. 미병합 SDK 코드를 설치하거나 SDK를 패치하지 않았다. 원문 개발 로그·요청 헤더·쿠키·설정은 업로드하지 않는다. 실패한 실행을 성공으로 집계하지 않으며, 후속 전체 실행의 결과는 Actions에 남긴다.

변경한 CI 실행 방식으로 로컬에서 전체 Playwright **10개 통과, 실패0, 재시도0(6.1분)**를 다시 확인했다. 30개 단위 테스트·요청 큐 검사·Wrangler 재시작 영속성 검사도 통과했다. 분리된 인스턴스의 native workerd 강제 종료가 CI 서버의 exit code 1로 이어짐을 확인하여 자동 재시작으로 실패가 숨겨지지 않게 했다. 임의의 입력·토큰 모양 문자열을 사용한 로그 필터 검사도 통과했으며 실제 credential은 사용하지 않았다.
